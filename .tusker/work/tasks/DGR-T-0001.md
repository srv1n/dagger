# DGR-T-0001 · Support honest multiple-root DAG definitions in dagger-workflow-core

## Intent

Allow one workflow to begin from more than one real node. A node that has no
input from another node is a true root. The compiler must keep those roots as
they are. It must not add a hidden first action just to make the graph look
serial.

This matters because RZN sends a typed graph to Dagger. References between node
outputs and inputs define the edges. Independent roots must become ready in the
same deterministic order, and a downstream node must wait until every referenced
value is complete. RZN cannot adopt this contract until this upstream task is
proved in the sibling Dagger repository.

Done means a published definition with two independent roots validates, runs,
resumes, and converges on its terminal node. The stored revision and run record
contain the authored nodes only. No synthetic node, second scheduler, or hidden
edge is present.

## Acceptance

| ID | Outcome | Proof |
|---|---|---|
| A1 | The JSON/YAML contract derives a root set from incoming output references. A definition with two independent action roots and one downstream terminal node validates without an `entry_node_id` requirement or an injected start node. | `command: cargo test -p dagger-workflow-core --all-features --lib multiple_root` |
| A2 | Reference bindings remain the only dependency edges. A node with references to both roots is not ready until both outputs succeed; an unrelated root may run independently. Readiness and persisted topological ranks are deterministic when the input node order changes. | `command: cargo test -p dagger-workflow-core --all-features --lib root_set_determinism` |
| A3 | Validation still rejects unknown node references, cycles, overlapping target pointers, missing terminal paths, and malformed root/output bindings. It does not accept a fake root as a compatibility shortcut. | `command: cargo test -p dagger-workflow-core --all-features --lib multiple_root_invalid` |
| A4 | `WorkflowRevision`, `WorkflowEngine::start`, `tick`, and resume/recovery use the derived root set. Runs execute each root once, fence completions correctly, and reach the one authored `Succeed` node without a compiler-created node or a new scheduler. | `command: cargo test -p dagger-workflow-core --all-features --test w3_engine multiple_root` and `command: cargo test -p dagger-workflow-core --features sqlite,conformance --test w8_recovery multiple_root` |
| A5 | The canonical schema and human documentation describe one honest multi-root contract, the exact root derivation rule, and the changed public field/API. Existing one-root reference workflows remain valid. | `command: cargo fmt --all -- --check` plus `command: cargo test -p dagger-workflow-core --all-features --test w1_definition` |

## Non-goals

- Do not add a compiler-created first node or other synthetic action/node.
- Do not add a scheduler, trigger, cron, webhook, agent harness, or RZN runtime.
- Do not add an authored dependency list; dependencies come only from typed
  references.
- Do not redesign action pins, schemas, storage, auth, credentials, or effects.
- Do not preserve an unpublished invalid definition merely because it used the
  old single-entry field. The project is pre-launch and may make this contract
  change directly.
- Do not edit the RZN backend checkout. RZN's pin and adapter work is a separate
  downstream task after this exact Dagger change is committed.

## Implementation notes

Builder appendix — implement only the upstream Dagger contract. Verify each path
against the checkout before editing.

- Execution tier: `gpt-5.6-sol` at `medium`. This is the deliberately hard
  engine/schema/recovery contract; do not raise the reasoning tier.
- File map:
  - `dagger-workflow-core/src/definition/mod.rs`: `WorkflowDefinition`, binding
    validation, reachability, root derivation, and canonical topological ranks.
  - `dagger-workflow-core/schema/workflow-definition-0.1.json`: remove or replace
    the single-entry requirement and describe the root rule.
  - `dagger-workflow-core/src/revision.rs`: persist the derived root set and any
    public revision shape needed by the engine.
  - `dagger-workflow-core/src/engine.rs`: seed and advance all true roots; do not
    manufacture a node or edge.
  - `dagger-workflow-core/src/conformance.rs` and the existing `tests/w1_*`,
    `tests/w3_engine.rs`, `tests/w8_recovery.rs`: positive, negative, ordering,
    and takeover fixtures.
  - `docs/system/workflow-definitions.md` and `docs/system/workflow-core.md`:
    explain the root set, reference-derived edges, and deterministic readiness
    in Simplified Technical English.
- Contract rules:
  - A root is a declared node with no incoming `node_output` binding.
  - `constant`, `run_input`, and `artifact_ref` sources do not create graph
    edges. A `node_output` source creates exactly one edge from its named node.
  - All declared nodes must be reachable from the derived root set. There is one
    authored reachable `Succeed` node; `Fail` remains allowed per the current
    engine contract.
  - Canonical ranks use the existing deterministic lexical Kahn rule. Do not use
    YAML order, hash-map iteration, wall-clock order, or task completion order.
  - Preserve the current input/output pointer and action-pin validation rules.
- External prerequisite: the RZN backend must later pin this exact Dagger commit
  and prove the pin. This task does not change any RZN path.
